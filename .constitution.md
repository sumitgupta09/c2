# Project Constitution — Gupta Corp Support Desk

**Equivalent to Spec-Kit `.constitution.md`** — non-negotiable rules for humans and AI agents.

## 1. Spec-first (no vibe coding)

- Read relevant `spec/*.md` before writing code.
- Update spec before changing behaviour.
- One layer or one user story per implementation prompt.
- Never prompt: "build the entire application."

## 2. Architecture

- **Backend:** Java 21, Spring Boot 3, layered (controller → service → repository).
- **Frontend:** Next.js App Router, TypeScript.
- **State machine** enforced in service layer only — never in controller or UI alone.
- **DTOs** at API boundary — never expose JPA entities.

## 3. Security

- No secrets in git (use `.env`, `${JWT_SECRET}`).
- No `eval`, no disabled TLS, no permissive production CORS.
- Demo passwords only in seeder/docs — never in production config.

## 4. Testing

- State machine: unit tests (`TicketStatusMachineTest`).
- API: integration tests (`TicketApiIntegrationTest`).
- Persistence: `PersistenceIntegrationTest` for restart survival.
- Run `mvn test` and `./scripts/smoke-all.sh` before marking work complete.

## 5. Workflow (Spec-Kit mapping)

| Step | Artifact |
|------|----------|
| Constitution | This file + `rules/` |
| Specify | `spec/requirements.md`, `docs/requirements-analysis.md` |
| Plan | `spec/architecture.md`, `spec/api-contract.md`, … |

| Review | `commands/review-code.md`, `commands/review-spec.md`, `commands/self-critique.md` |

## 6. AI behaviour

- Follow `rules/java-springboot.md`, `rules/api-standards.md`, `rules/testing.md`.
- Record prompts in `docs/prompt-history.md`.
- Record AI mistakes in `docs/ai-review-notes.md`.
- Use MCP tools in `mcp-server/` for ticket lookups when debugging.
